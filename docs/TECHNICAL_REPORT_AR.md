## 1. خلاصة تنفيذية

**التوصية:** خادم ذكاء اصطناعي مشترك وآمن، مع **عميل ويب واحد مشترك (TypeScript + Three.js + WebXR)** يعمل على:

- **iPhone Safari:** مشهد ثلاثي الأبعاد مضمّن في الصفحة (inline) مع المحادثة الصوتية.
- **Quest Browser:** جلسة WebXR غامرة. تعمل في وضع VR بالمجلس الكامل، وفي وضع MR بالرؤية المباشرة (Passthrough).
- **Quest APK مستقل:** نفس العميل مغلّف كتطبيق PWA عبر أداة Meta الرسمية (Bubblewrap بنسخة Meta Quest). يُبنى تلقائيًا في GitHub Actions.

**المحرك الصوتي الأساسي (بعد التحديث 1):** Gemini Live بالطبقة المجانية، بمفاتيح مؤقتة قصيرة العمر. (كان المقترح الأصلي OpenAI Realtime.) معه **مسار بديل متتالٍ** (تعرّف كلام ← نموذج لغوي ← تحويل نص إلى كلام بصوت سعودي مصمَّم)، وكلاهما خلف واجهة موحّدة. يُحسم الاختيار النهائي بـ**اختبار مقارنة صوتي** يقيّمه المالك بنفسه، لأن الصوت النجدي الأصيل غير مضمون عند أي مزوّد.

**هل يكفي محرك واحد لكل المنصات؟** عمليًا لا يوجد محرك ألعاب أصلي (Unity أو Godot) يقدّم تجربة جيدة على iPhone Safari وعلى Quest معًا. الويب هو التقنية الوحيدة التي تعمل فعليًا على المنصتين بنفس الشيفرة. لكن البنية الصحيحة ليست «محركًا واحدًا»، بل:

**خادم ذكاء اصطناعي مشترك + نواة منطق مشتركة + واجهات عرض خاصة بكل منصة.**

بهذا التصميم، إذا ثبت لاحقًا أن تطبيق Quest يحتاج تقنية أصلية، يُستبدل عميل Quest وحده، ويبقى الخادم والشخصية ومحرك القصص وأصول glTF كما هي.

**السبب الحاسم لاختيار الويب: إلغاء الصدى (AEC).**
- شرط المقاطعة يتطلب أن يسمع الميكروفون المستخدم أثناء كلام الشايب من سماعات الجهاز نفسه.
- بدون إلغاء صدى، يلتقط الميكروفون صوت الشايب ويظنه مقاطعة، فيقاطع نفسه.
- `getUserMedia({echoCancellation:true})` مع تشغيل الصوت عبر WebRTC يوفّر إلغاء الصدى في المتصفحات جاهزًا.
- في المقابل، ميكروفون Godot وUnity الافتراضي على Android لا يطبّق إلغاء الصدى، ويحتاج إضافات أصلية مخصصة. ⚠️ يجب قياس جودة إلغاء الصدى فعليًا على Quest وiPhone.

## 4. معمارية Quest (VR + MR)

```
Quest APK (PWA/Bubblewrap)  ──يفتح مباشرة──▶  جلسة WebXR immersive-ar (أو immersive-vr احتياطيًا)
   │
   ├─ مشهد Three.js: المجلس الإجرائي + الشايب الإجرائي + صوت مكاني (PannerNode/PositionalAudio)
   ├─ نواة المحادثة المشتركة (packages/core)
   └─ واجهة XR بسيطة: لوحة عائمة RTL + أزرار المتحكّم/اليد
```

### التبديل بين VR وMR بدون قطع المحادثة
- تُفتح جلسة `immersive-ar` واحدة.
- **وضع VR:** يُرسم المجلس كاملًا ومعتمًا فوق الرؤية المباشرة، فلا يرى المستخدم الغرفة.
- **وضع MR:** يُخفى المجلس ويبقى الشايب (ومعه سجادته اختياريًا).
- التبديل يتم داخل نفس الجلسة، فاتصال WebRTC وحالة القصة لا يتأثران.
- إذا لم يكن `immersive-ar` متاحًا: نستخدم `immersive-vr`، ويكون التبديل بإنهاء الجلسة وفتح أخرى، مع بقاء الصفحة واتصال الصوت حيّين. ⚠️ يحتاج تحققًا على الجهاز.

### وضع الشخصية في MR
1. `hit-test` على الأرضية.
2. ثم plane-detection والمرساة (anchors) إن أُذن بها.
3. وإلا وضع يدوي: الشخصية أمام المستخدم على بعد ~1.5م، على ارتفاع الأرض المقدّر من `local-floor`.
- أزرار لإعادة الوضع والتدوير.
- رفض إذن «بيانات المساحة» لا يوقف التطبيق، بل ينتقل تلقائيًا للوضع اليدوي.

### الأداء
- الهدف 72Hz.
- ميزانية تقريبية: أقل من 100 ألف مثلث، أقل من 50 draw call، إضاءة مخبوزة مع ضوء واحد ديناميكي، بدون ظلال لحظية أو بظل مزيّف.
- ⚠️ الأرقام تقديرية وتُقاس على Quest 3S (الأضعف) في M1.

### التثبيت والاختبار بدون كمبيوتر (خطر مهم)
- **أسرع طريق للتجربة لا يحتاج APK:** يفتح المالك رابط HTTPS في متصفح Quest، ويحصل على نفس الوظائف كاملة.
- **تثبيت APK يدويًا (Sideload)** يتطلب وضع المطوّر وجهاز كمبيوتر أو هاتف Android عبر adb. الآيفون لا يكفي.
- **البديل المقترح:**
  1. إنشاء تطبيق في لوحة مطوّري Meta Horizon.
  2. GitHub Actions يرفع الـ APK إلى «قناة إصدار» خاصة (release channel) عبر `ovr-platform-util`، باستخدام أسرار GitHub.
  3. يُضاف المالك كمختبِر، فيثبّت التطبيق من المتجر على النظارة مباشرة.
- ⚠️ قيود هذا البديل:
  - يحتاج حساب مطوّر Meta موثّقًا.
  - توفر نسخة Linux من الأداة غير مؤكد. البديل منفّذ Windows في GitHub Actions.
- الـ APK سيُرفع أيضًا كـ artifact للتحميل المباشر في كل الأحوال.

### الشرط «لا يتطلب متصفحًا»
تطبيق الـ PWA يظهر في مكتبة التطبيقات ويُفتح كتطبيق مستقل بدون واجهة المتصفح، **لكنه يعمل داخليًا بمحرك Quest Browser**. أذكر ذلك بوضوح:
- إن كان المقصود «تطبيق مستقل في المكتبة» فالشرط متحقق.
- إن كان المقصود «تطبيق أصلي بدون محرك ويب» فالمسار البديل هو Spatial SDK، بتكلفة شيفرة ثانية للعرض.

## 5. معمارية iPhone

- **التطبيق:** نفس العميل يُنشر على **GitHub Pages** (HTTPS مجاني)، مع ملف manifest اختياري لتثبيته كـ PWA.
- **العرض:** Three.js (WebGL2) inline، بكاميرا ثابتة أمام الشايب مع لمس للالتفات والتكبير. واجهة RTL متجاوبة.
- **الصوت في Safari:**
  - زر «ابدأ السالفة» إلزامي، لفتح `AudioContext` وطلب إذن الميكروفون بلمسة من المستخدم.
  - رسائل واضحة عند رفض الإذن، مع إرشاد لإعدادات Safari.
  - معالجة انقطاع الصوت عند قفل الشاشة أو المكالمات (`visibilitychange` و`interruption`).
- ⚠️ **مخاطر Safari المعروفة:**
  - توجيه الصوت للسماعة الأمامية الخافتة بدل السماعة الخارجية أثناء تشغيل الميكروفون.
  - مشكلات تاريخية مع تحليل صوت WebRTC الوارد عبر Web Audio (نحتاجه لحركة الفم).
  - سلوك الميكروفون داخل PWA مثبّتة على الشاشة الرئيسية.
  - كلها تُختبر في M2، ولكل منها بديل: تشغيل PCM عبر WebSocket وAudioWorklet، أو الاكتفاء بفتح Safari بدون تثبيت.
- **تطبيق iOS أصلي مع ARKit:** لا أوصي به الآن، لأنه يحتاج حساب Apple Developer (99$ سنويًا) وTestFlight، ويضيف شيفرة ثالثة. يُعاد تقييمه بعد M5 إن طُلب وضع AR على الآيفون.
- **لن نعد بتطابق ميزات XR:** الآيفون معاينة ثلاثية الأبعاد بدون AR.

- **هذه أرقام تقديرية يجب قياسها.** القصص الطويلة ترفع الكلفة لأن السياق يكبر، والحل تلخيص السياق دوريًا.

### التوصية الصوتية
1. **واجهة `VoiceSession` موحّدة** في النواة المشتركة: `start / interrupt / cancel / onState / onTranscript / onAudioLevel`. يوجد تحتها مُشغّلان:
   - `RealtimeAdapter` (OpenAI، وقابل لإضافة Gemini).
   - `CascadeAdapter` (عبر خادمنا).
2. **نبدأ بـ OpenAI Realtime** لأنه أسرع طريق لمحادثة حقيقية بمقاطعة طبيعية وزمن منخفض.
3. **اختبار مقارنة صوتي (بداية M2):**
   - 10 نصوص نجدية: تحية، سالفة، مثل، سؤال مقاطع، وغيرها.
   - تُمرَّر عبر 3–4 مسارات، ويقيّمها المالك على الآيفون **بدون معرفة اسم المزوّد**.
   - يُسجَّل لكل مسار: الدقة، اللهجة، الطبيعية، والزمن.
4. **إن لم يكن أي صوت جاهز مقنعًا نجديًا** (وهو الاحتمال الأرجح ⚠️): التوصية **تسجيل ممثل صوتي سعودي كبير بالسن بعقد وموافقة مكتوبة**، واستنساخه احترافيًا (ElevenLabs PVC أو ما يعادله) واستخدامه في المسار المتتالي. أي استنساخ بدون موافقة صريحة ممنوع.

### المقاطعة (barge-in)
- **التشغيل:** يمر صوت الشايب عبر عنصر WebRTC ليستفيد من إلغاء الصدى.
- **الاكتشاف:** VAD من الخادم/المزوّد، مع VAD محلي احتياطي.
- **عند اكتشاف كلام المستخدم:**
  1. إيقاف الصوت فورًا محليًا.
  2. إرسال `response.cancel`.
  3. قصّ نص الرد المسجَّل إلى ما سُمع فعلًا (`conversation.item.truncate`)، حتى يعرف الشايب أين توقف في القصة.
- **استئناف القصة:** حالة «القصة الحالية + آخر نقطة مسموعة» محفوظة في ذاكرة الجلسة، فيقدر يكمل بـ«وين وصلنا… إيه».
- منع تداخل الأصوات: مشغّل صوت واحد فقط، وطابور الردود ممنوع.

### الشخصية والقصص
- **إعداد الشخصية في ملفات** (`persona/ar-najdi.md`) مفصولة عن الشيفرة، وتشمل الأسلوب والعمر وتنويع العبارات ومنع التكرار.
- **قاعدة الأمانة التاريخية:** يميّز الشايب صراحةً بين:
  - «سالفة من خيالي»
  - «حكاية متوارثة / من التراث»
  - «معلومة تاريخية معروفة»
  - ولا يقدّم تواريخ أو أسماء مخترعة كحقائق.
- **ذاكرة الجلسة:** القصة الحالية، الموضوع، التفاصيل المذكورة، المقاطعات، والأسئلة. تُلخّص دوريًا لضبط الكلفة.
- **لا ذاكرة دائمة الآن.** لا تُخزَّن تسجيلات صوتية في خادمنا. يُراجَع إعداد الاحتفاظ بالبيانات لدى المزوّد.

## 7. الخادم الآمن المقترح

**المنصة:** Cloudflare Workers + Durable Objects بلغة TypeScript، وتُنشر من GitHub Actions.
- سبب الاختيار: مجاني أو ~5$ شهريًا، قريب من المستخدم، ولا يحتاج إدارة خوادم.
- بديل مكافئ: Fly.io أو Render.

| النقطة | الوظيفة |
|---|---|
| `POST /v1/session` | يتحقق من هوية الجهاز، ثم يطلب من OpenAI **مفتاحًا مؤقتًا** (client secret قصير العمر). تعليمات الشخصية والصوت والأدوات تُحدَّد **في الخادم**، والمفتاح الدائم لا يغادره أبدًا |
| `WS /v1/cascade` | ترحيل للمسار المتتالي داخل Durable Object يحمل مفاتيح المزوّدين |
| `POST /v1/auth` | رمز دعوة للمالك والمختبرين، يُستبدل برمز جلسة قصير (JWT) |

**الحماية:**
- مفاتيح المزوّدين في Cloudflare Secrets وGitHub Secrets فقط.
- لا أسرار في الـ APK أو الـ PWA أو المستودع، مع فحص أسرار تلقائي في CI.
- حد معدل لكل جهاز ولكل IP.
- حد أقصى لمدة الجلسة (مثلًا 20 دقيقة).
- **سقف إنفاق يومي** يوقف إصدار الجلسات عند تجاوزه.
- قائمة origins مسموحة (CORS).
- سجلات بدون محتوى المحادثات.
- ⚠️ **خطر:** في وضع WebRTC المباشر، يستطيع العميل تعديل إعدادات الجلسة عبر قناة البيانات. **المعالجة:** قفل الإعدادات في الخادم، مع اتصال تحكم جانبي من الخادم (sideband) إن أتاحه المزوّد. ⚠️ يحتاج تحققًا.

## 8. معمارية الشيفرة المشتركة

> **تنفيذ المرحلة الأولى:** بدأنا بحزمة واحدة (`src/core`, `src/scene`, `src/xr`, `src/ui`, `src/i18n`) بنفس الفصل بين الطبقات. هذا يغني عن أدوات monorepo إضافية الآن. نفصلها إلى حزم مستقلة عند إضافة الخادم في المرحلة الثانية.

```
/
├─ packages/
│  ├─ core/          ← حالة المحادثة، آلة حالات السلوك، ذاكرة القصة، VoiceSession، i18n (بدون أي اعتماد على العرض)
│  ├─ voice-realtime/← مشغّل OpenAI Realtime (WebRTC)
│  ├─ voice-cascade/ ← مشغّل المسار المتتالي (WebSocket)
│  ├─ scene/         ← Three.js: المجلس الإجرائي، الشايب الإجرائي خلف واجهة CharacterRig
│  └─ xr/            ← جلسات WebXR، التبديل VR/MR، الوضع في الغرفة، واجهة XR
├─ apps/
│  ├─ web/           ← iPhone + Quest Browser + سطح المكتب (نقطة دخول واحدة تكتشف القدرات)
│  └─ quest-pwa/     ← إعداد Bubblewrap/Meta لتوليد APK
├─ server/           ← Cloudflare Worker
├─ persona/          ← ملفات الشخصية وفئات القصص (عربي/إنجليزي)
├─ locales/          ← ar.json / en.json (الواجهة فقط)
└─ .github/workflows/← فحص، اختبارات، نشر Pages، نشر الخادم، بناء APK والتحقق منه
```

- **`CharacterRig`:** واجهة تحتوي `setState(idle|listening|thinking|speaking|storytelling|reacting|interrupted)` و`setMouthOpen(0..1)` و`lookAt()` و`gesture()` و`setExpression()`.
  - الشخصية الإجرائية تطبّقها الآن.
  - نموذج GLB المزوّد بهيكل عظمي لاحقًا يطبّق نفس الواجهة، **بدون أي تعديل في محرك المحادثة**.
- **حركة الفم في البداية:** تتبع **سعة الصوت الحقيقية** لصوت الشايب (تحليل الإشارة)، وليست حركة عشوائية. مزامنة الحروف (visemes) تأتي في المرحلة 4 أو 6.
- **فصل اللغات بشكل مستقل:** لغة الواجهة، ولغة التعرّف، ولغة الرد، والصوت، وملف الشخصية.
- **إدارة الحزم:** pnpm workspaces مع إصدارات مثبّتة وlockfile.
- **أدوات البناء:** Vite (MIT) وTypeScript وVitest، بدون اعتماديات غير ضرورية.

## 9. سير عمل GitHub فقط

| سير العمل | المحتوى |
|---|---|
| `ci.yml` | فحص البنية، lint، typecheck، اختبارات الوحدة، فحص الأسرار |
| `pages.yml` | بناء العميل ونشره على GitHub Pages، والرابط يظهر في ملخص التشغيل |
| `server.yml` | نشر الخادم على Cloudflare (بأسرار GitHub) |
| `quest-apk.yml` | بناء الـ APK بـ Bubblewrap، والتحقق منه بـ `aapt2 dump badging` و`apksigner verify` (اسم الحزمة، الإصدار، الأذونات، التوقيع)، ثم رفعه كـ artifact، واختياريًا رفعه لقناة إصدار Meta |

- **التوقيع:** للتصحيح يُستخدم مفتاح مؤقت يُولَّد في CI. للإنتاج يُستخدم keystore مخزّن في GitHub Secrets، ولا يُودَع في المستودع أبدًا.
- **ملاحظة:** Bubblewrap يحتاج رابط manifest منشورًا. لذلك يُشغَّل `quest-apk.yml` بعد نجاح `pages.yml`.

## 10. تقدير تكاليف التشغيل (تقديري)

> **بعد التحديث 1، التكلفة الفعلية للمشروع = صفر.** الأرقام التالية مرجع فقط إذا قرر المالك لاحقًا استخدام مزوّد مدفوع.

| البند | الكلفة |
|---|---|
| الاستضافة (GitHub Pages) | مجاني |
| الخادم (Cloudflare Workers) | مجاني للتجارب، ~5$ شهريًا للخطة المدفوعة |
| GitHub Actions | ضمن الحصة المجانية غالبًا للمستودع |
| حساب مطوّر Meta | مجاني ⚠️ (يحتاج توثيقًا) |
| **الذكاء الاصطناعي، Realtime كامل** | ~0.08–0.20$/دقيقة، أي **~1.6–4$ لجلسة 20 دقيقة** |
| **الذكاء الاصطناعي، Realtime mini** | ~0.03–0.07$/دقيقة، أي ~0.6–1.4$ لجلسة 20 دقيقة |
| **الذكاء الاصطناعي، المسار المتتالي** | ~0.05–0.12$/دقيقة (معظمه تحويل النص إلى كلام) |
| ممثل صوتي واستنساخ (اختياري) | تكلفة لمرة واحدة حسب العقد، واشتراك المزوّد ~22–99$ شهريًا ⚠️ |

**مثال:** مالك ومختبران × 30 دقيقة يوميًا × 30 يومًا = 45 ساعة شهريًا:
- ~220–540$ بالنموذج الكامل.
- ~80–190$ بنموذج mini.

**التوصية:** نبدأ بنموذج mini للتطوير، ونستخدم الكامل للمقارنة، مع **سقف إنفاق يومي إلزامي**.

> **ملاحظة:** الأسعار مأخوذة من صفحة أسعار OpenAI عبر مقتطفات البحث (يوليو 2026). يجب التحقق منها مباشرة قبل اعتماد الميزانية.

## 13. القيود التقنية المعلنة

- لا WebXR ولا AR على iPhone Safari. الآيفون معاينة ثلاثية الأبعاد فقط.
- تطبيق Quest بالمسار الموصى به يعمل بمحرك المتصفح داخليًا، رغم أنه تطبيق مستقل في المكتبة.
- اكتشاف الغرفة والأسطح في MR غير مضمون دائمًا، ولذلك يوجد وضع يدوي.
- لا ضمان لنطق نجدي أصيل قبل الاختبار.
- لا يمكن ادعاء التوافق أو الأداء قبل القياس على الأجهزة.
- التشغيل يتطلب اتصال إنترنت، ولا يوجد وضع غير متصل للمحادثة.

## 14. التوصية النهائية

> بعد التحديث 1: المزوّد الافتراضي **Gemini Live المجاني**، وكل الاستضافة على خطط مجانية.

1. **الخادم:** Cloudflare Workers آمن بمفاتيح مؤقتة، وسقف إنفاق، ورموز دعوة.
2. **العميل:** عميل ويب مشترك (TypeScript + Three.js + WebXR)، منشور على GitHub Pages للآيفون ومتصفح Quest، ومغلّف كـ APK لـ Quest عبر أداة Meta الرسمية.
3. **الصوت:** OpenAI Realtime كبداية، مع مسار متتالٍ يعتمد صوتًا سعوديًا مصمَّمًا أو ممثلًا مرخَّصًا، ويُحسم الاختيار بمقارنة يقيّمها المالك.
4. **بوابة قرار بعد M1:** إذا فشل الـ APK المغلّف على Quest في معايير الميكروفون أو إلغاء الصدى أو الأداء، يُبنى عميل Quest بـ Meta Spatial SDK مع الاحتفاظ بكل ما سواه.
